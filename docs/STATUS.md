## State (updated 2026-11-13)

- **Released:** 0.4.2 (GitHub Release, in-app updater); `main` points to `https://api.kara-kuyan.it-aul.ru` and ships **Pro CameraX 1.6.2 Document Capture + Canonical C++20 Native OCR (`tatar_ocr_core`) + Universal Remote Announcements** (`camera-pro-capture-v42`, `cpp-native-ocr-pipeline`, `remote-announcements-feed`, ADRs 0005, 0006 & 0010).

Demo data is gone from product code.
- **Pro CameraX 1.6.2 Live Document Capture (`ADR 0006`, `v0.4.2`)**: Unified 4:3 `FIT_CENTER` preview (`1280×960` analysis, `4200×3150` `JPEG 95` capture), hybrid `CAPTURE_MODE_ZERO_SHUTTER_LAG` / `CAPTURE_MODE_MAXIMIZE_QUALITY` (with `Camera2Interop` `EDGE_MODE_HIGH_QUALITY` + `NOISE_REDUCTION_MODE_FAST`), `+0.5 EV` white-paper metering, sheet-centroid `FocusMeteringAction` (`FLAG_AF | FLAG_AE`) + tap-to-focus + bounded `awaitFocusBeforeCapture` (`≤ 1200 ms`), OpenCV 5.0.0 denoised `Sobel P99` sharpness & 6×6 patch hotspot glare DQA, `1×` automatic silent retry on post-capture motion blur, ADR-0003 numeric `OcrCamera` shutter telemetry, and glassmorphic `Свет` + `1× / 1.4×` HUD controls.
- **Canonical C++20 On-device OCR (`third_party/tatar_ocr`, `tatar_ocr::NativeBlankScanner`)**: Upstream `DanisGaleev/tatar_ocr` (`v3-architecture-training` @ `d27477b`) connected as an unmodified Git submodule and compiled into `libtatar_ocr_jni.so` via Android NDK CMake (`TATAR_OCR_BUILD_PYTHON=OFF`, `-O3`, 16 KB page-aligned) sharing `org.opencv:opencv:5.0.0` Prefab (`OpenCV::opencv_java5`) and `onnxruntime-android:1.30.0` with `pipeline_spec.json` + `tatar_ocr_v4_handwritten39_int8.onnx` extracted into `context.filesDir`. Includes full EXIF 8-mode + CameraX `JPEG`/`YUV_420_888` `rotationDegrees` portrait normalization, `detect_markers_padded` live viewfinder lock, contour fallback acceptance, and multi-pass RGBA/ROI QR decoding. Verified on Android 16 (`arm64-v8a`) across 12 real handwritten sheets + rotated portrait EXIF sheet + phone camera photo: **`Acc_char = 96.88%` (`435/449`)**, **`Top-3 = 99.55%` (`447/449`)**, `portrait_exif_blank_01.jpg` exact match `True`, `test_blank_phone_photo.jpg` `8/8` words exact + QR.
- **Android 13–16 Notifications, Remote Announcements Feed & Background Sync (`ADR 0010`)**: `expo-notifications@~57.0.25` + `expo-background-task@~57.0.23` (`WorkManager`) via `NotificationsPort` and dual-source `AnnouncementsPort` (`GET /api/v1/announcements` + GitHub Pages CDN `announcements.json` with `ETag` `304` & SQLite cache, zero GMS/FCM dependency, zero student PII), 4 granular Android `NotificationChannel`s, 5 interactive `NotificationCategory` action sets, pull-to-refresh + external `https://` links on `/notifications`, and CLI publisher `pnpm run news:add`.
- **Teacher checking flow (v4 Prime)**: calibrated `τ = 85%` selective prediction; Fast-Track routing directly to `AssessmentResultScreen` with inline student switcher; **Zero-Touch** emerald swipe-right / 1-tap «Сохранить и следующий лист» (`→ /scan`) on 100%-confident sheets; **Spot-Focus** yellow `< 85%` cell highlight with 1-tap Top-3 candidate chips, `[Пусто]` chip, and a 39-letter Tatar uppercase bottom sheet (`TatarLetterPickerSheet`).

## Blocked / open items

- **OpenAPI** — the live server (`tatar-ocr.duckdns.org`) serves a much better spec (`docs/contracts/openapi-live-2026-09-19.json`: operationIds, 4xx, required fields; still no security scheme). Draft `openapi.yaml` is superseded but kept. Codegen not blocked by lint any more; semantic gaps and the offline-bundle 500 remain (`docs/contracts/contract-gaps.md` items 19–22).
- **Backend idempotency / re-check semantics** — `client_submission_uuid` upsert, ordering, partial-failure behavior unconfirmed; must not be invented client-side.
- **Grading mismatch** — 7/8 → grade 4 in API example vs scale that maps 87% → grade 5.
- **Android TalkBack end-to-end** — structural a11y labels added; a TalkBack pass on the real scan → review → save flow is still to do.
- **Decision thresholds** — `proposedThresholds` (p ≥ 0.8, lead ≥ 0.3) are unvalidated; first real sheet: 10/11 letters top-1, none wrongly accepted. Calibration on the 10 sheets pending. Backend `0.65` is only a hardcoded default.
- **QR identity** — QR carries no student id; identity comes from the name field (fuzzy roster match) or the teacher's pick.
- **Zero-photo evidence** — files, gallery and logs checked clean; network capture not yet done.
- **Reference phone details** — Samsung SM-S928B confirmed: Android 16/API 36, 1080×2340 at 450dpi, 384×832dp; SoC `SM8650` (Snapdragon 8 Gen 3), 8 cores, ~11.3 GB RAM (verified via adb 2026-09-19, `harness/changes/active/p0-camera-runtime-spike/evidence/device-and-models.md`). Benchmark done (`evidence/benchmark.md`).
- **Model class order** — guide says `Ә` last; measured models and the authors' pipeline PDF put `Ә` at index 1. Recorded in `docs/architecture/ocr-pipeline.md`; verify on handwriting (`contract-gaps.md` item 17).
- **Backend source obtained** — `github.com/DanisGaleev/tatar_ocr` @796601e read; preprocessing and sheet geometry ported exactly; several gaps clarified (`contract-gaps.md`, `docs/contracts/ocr-server-pipeline-reference.md`). Open: repo has no licence, `realdataset/` (real handwriting) needs the authors' permission, accuracy claims conflict (96.97% vs 94.28%).
- **Live backend** — restored 2026-09-19; `offline-bundle` for `TAT-2026-Q1` returns 500 and `blank.pdf` has 4 questions vs 8 announced (`contract-gaps.md` items 21–22).
- **Sheet geometry / blank cells** — marker position/size, row and cell coordinates absent from the contract; blank-cell rule client-defined (`docs/contracts/contract-gaps.md` items 15–16).
- **Weak auth model** — `X-Teacher-UUID` is bearer-equivalent demo identity; production auth/rotation/revocation is an unresolved backend requirement.
- **OS-level capture** — `FLAG_SECURE` vs demo recording on camera/result surfaces undecided.
- **Model license/version** — not embedded in ONNX metadata; manifest proposed.
