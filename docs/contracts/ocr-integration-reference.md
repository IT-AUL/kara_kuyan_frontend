## ЧАСТЬ 1. Требования к входному тензору модели

Модель ожидает на вход тензор со следующими параметрами:
* **Форма (Shape):** `[Batch_Size, 1, 64, 64]` (для одиночной буквы: `[1, 1, 64, 64]`).
* **Тип данных (Dtype):** `float32`.
* **Каналы:** `1` (градации серого / grayscale).
* **Диапазон значений пикселей:** строго от `[-1.0]` до `[+1.0]`:
  * `+1.0` (или близко к 1.0) — белый фон листа бумаги.
  * `-1.0` (или близко к -1.0) — тёмные чернила ручки.

## ЧАСТЬ 2. Пошаговая предобработка изображения (Pre-processing Pipeline)

Пайплайн состоит из 5 обязательных шагов.

### Шаг 1. Обрезка рамки и отступов клетки (Margin Erosion / Trim)
Если символ вырезается из бланка с сеткой или тетради в клетку, линии сетки часто попадают в края вырезки (1–5 пикселей). Если их оставить, модель может принять вертикальную полосу сетки за элементы букв (например, превратить `Ә` в `д`, а `А` в `Һ`).
* **Решение:** Срезать **3–5%** внешнего периметра вырезки:
  $$\text{crop} = \text{image}[y_{\text{trim}} : H - y_{\text{trim}},\ x_{\text{trim}} : W - x_{\text{trim}}]$$

### Шаг 2. Приведение к квадрату с сохранением пропорций (Square Aspect-Ratio Padding)
Буквы имеют разные пропорции: буква `Ш` или `Ж` широкая, а `І` или `Г` узкая. Если сразу сжать прямоугольник до $64 \times 64$, буква геометрически деформируется.
* **Решение:** 
  1. Вычисляется максимальная сторона: $S = \max(H, W)$.
  2. Определяется цвет фона бумаги (медиана пикселей по внешнему периметру вырезки).
  3. Создаётся квадратное изображение $S \times S$, залитое цветом фона.
  4. Исходная буква центрируется по середине квадрата.

### Шаг 3. Перевод в Grayscale и адаптивная нормализация контраста
При съемке на смартфон освещение нестабильно: бывают тени, блики от вспышки или серая бумага. Модель обучалась на **Percentile Min-Max Stretching** (растяжение гистограммы по 2-му и 98-му процентилям):
1. Находим $P_2$ (2% самых темных пикселей — чернила) и $P_{98}$ (98% светлых пикселей — фон).
2. Растягиваем динамический диапазон чернил:
   $$I_{\text{norm}} = \text{clip}\left(\frac{I - P_2}{P_{98} - P_2 + 10^{-5}} \times 240.0 + 10.0,\ 0,\ 255\right)$$
Это убирает серую дымку, делая фон равномерно белым, а штрихи ручки — контрастными.

### Шаг 4. Ресайз до $64 \times 64$
* Используется интерполяция **`cv2.INTER_AREA`** (она предотвращает исчезновение тонких линий шариковой ручки при сжатии высокого разрешения).

### Шаг 5. Нормализация диапазона до $[-1.0, 1.0]$
1. Деление на `255.0` $\rightarrow$ диапазон $[0.0, 1.0]$.
2. Вычитание `0.5` и деление на `0.5`:
   $$\text{tensor} = \frac{\frac{I_{64}}{255.0} - 0.5}{0.5}$$

## ЧАСТЬ 3. Готовый Python-код подготовки (Копируй и используй)

Этот код можно использовать как для **PyTorch**, так и для **ONNX Runtime** или **TFLite**:

```python
import cv2
import numpy as np
import torch

def preprocess_cell_image(image_input, margin_trim_pct=4):
    """
    Предобработка вырезанной клетки под формат Tatar OCR Net.
    :param image_input: np.ndarray (BGR или Grayscale) или путь к файлу (str)
    :param margin_trim_pct: Процент среза краев для удаления линий сетки бланка (0..8%)
    :return: torch.Tensor формы [1, 1, 64, 64] со значениями в [-1.0, 1.0]
             и np.ndarray формы (1, 1, 64, 64) для ONNX Runtime.
    """
    if isinstance(image_input, str):
        img_bgr = cv2.imread(image_input)
    else:
        img_bgr = image_input.copy()

    orig_h, orig_w = img_bgr.shape[:2]

    # 1. Срез внешних границ от случайных линий сетки
    if margin_trim_pct > 0:
        trim_y = int(orig_h * (margin_trim_pct / 100.0))
        trim_x = int(orig_w * (margin_trim_pct / 100.0))
        y1, y2 = trim_y, max(trim_y + 1, orig_h - trim_y)
        x1, x2 = trim_x, max(trim_x + 1, orig_w - trim_x)
        img_cropped = img_bgr[y1:y2, x1:x2]
    else:
        img_cropped = img_bgr

    # 2. Дополнение до квадрата (Square Padding) цветом фона
    ch, cw = img_cropped.shape[:2]
    sq_size = max(ch, cw)
    
    # Оценка цвета фона по краям
    edge_pixels = np.concatenate([
        img_cropped[0, :, :], img_cropped[-1, :, :],
        img_cropped[:, 0, :], img_cropped[:, -1, :]
    ], axis=0)
    bg_color = np.median(edge_pixels, axis=0).astype(np.uint8)

    padded = np.full((sq_size, sq_size, 3), bg_color, dtype=np.uint8)
    py = (sq_size - ch) // 2
    px = (sq_size - cw) // 2
    padded[py:py + ch, px:px + cw] = img_cropped

    # 3. Grayscale + Перцентильная нормализация контраста
    gray = cv2.cvtColor(padded, cv2.COLOR_BGR2GRAY)
    p_lo = np.percentile(gray, 2)
    p_hi = np.percentile(gray, 98)
    norm_gray = np.clip(
        (gray.astype(np.float32) - p_lo) / (p_hi - p_lo + 1e-5) * 240.0 + 10.0,
        0, 255
    ).astype(np.uint8)

    # 4. Ресайз до 64x64
    inp_64 = cv2.resize(norm_gray, (64, 64), interpolation=cv2.INTER_AREA)

    # 5. Приведение к диапазону [-1.0, 1.0] и добавление измерений [1, 1, 64, 64]
    tensor_np = ((inp_64.astype(np.float32) / 255.0) - 0.5) / 0.5
    tensor_np = tensor_np[np.newaxis, np.newaxis, :, :]  # Форма: (1, 1, 64, 64)

    tensor_torch = torch.from_numpy(tensor_np)
    return tensor_torch, tensor_np
```

## ЧАСТЬ 5. Как интерпретировать результат (Post-processing & Decision Making)

### 1. Превращение логитов в вероятности (Softmax)
На выходе модели находятся не проценты, а сырые числа (logits). Чтобы получить вероятность от $0\%$ до $100\%$, к ним применяется функция Softmax:
$$P_i = \frac{e^{z_i}}{\sum_{j=1}^{39} e^{z_j}}$$

### 2. Извлечение Top-1 и Top-K кандидатов
```python
# Для ONNX Runtime / NumPy:
logits = session.run(None, {'input': tensor_np})[0][0]
exp_logits = np.exp(logits - np.max(logits))
probs = exp_logits / np.sum(exp_logits)

# Top-1 результат
top1_idx = int(np.argmax(probs))
top1_char = TATAR_UPPERCASE[top1_idx]
top1_conf = float(probs[top1_idx]) * 100.0

# Top-3 кандидата
top3_indices = np.argsort(probs)[-3:][::-1]
candidates = [(TATAR_UPPERCASE[i], float(probs[i]) * 100.0) for i in top3_indices]
```

### 3. Производственные пороги уверенности (Business Logic в приложении)

На основе калибровочных тестов на реальных рукописных бланках выработаны следующие правила для мобильного приложения:

| Диапазон уверенности Top-1 | Статус распознавания | Действие мобильного приложения |
| :---: | :---: | :--- |
| **$\ge 80.0\%$** | **Высокая уверенность (Green)** | Принимаем результат автоматически без подтверждения пользователя. Точность на этом уровне $\mathbf{>98.5\%}$. |
| **$50.0\% - 79.9\%$** | **Средняя уверенность (Yellow)** | Буква распознана, но рекомендуется проверить Top-2 и Top-3 кандидатов (например, если ожидается конкретная буква из проверочного словаря урока). |
| **$< 50.0\%$** | **Неуверенно / Подозрение на грязь (Red)** | Клетка заполнена неразборчиво, смазана или зачеркнута. Предложить ученику/учителю кликнуть на клетку и выбрать правильную букву из предложенных Top-3. |

### 4. Проверка по шаблону урока (Verification against ground-truth)
В приложении «Дәресханә» обычно известно, какое слово или букву должен был написать ученик в конкретную клетку:
* Если `expected_char == top1_char` $\rightarrow$ Буква засчитывается как верная.
* Если `expected_char` находится в **Top-3** с вероятностью $>15\%$ $\rightarrow$ скорее всего, у ученика нестандартный почерк (например, оторванный крючок у `Щ` или острый хвостик у `Җ`), приложение может пометить клетку для быстрой валидации учителем.
