# Что нужно от бэкенда, чтобы приложение работало целиком (2026-09-19)

Основание: `harness/changes/active/backend-integration/evidence/audit-2026-09-19.md` и живые проверки. Приоритеты: **P0** блокирует функционал, **P1** нужно для демо/продукта, **P2** улучшения. Пункты из `contract-gaps.md` (15–24) не повторяются, кроме отмеченных «→ gap N».

## P0 — без этого функционал не заработает
1. ~~**`offline-bundle` для `TAT-2026-Q1` отдаёт 500**~~ **исправлено (проверено 2026-09-19 вечером)**; осталось расхождение: метаданные говорят о 2 вариантах, пакет содержит 1 (у созданных через конструктор заданий 200). Починить или убрать сид. → gap 21
2. ~~**Связка «задание ↔ класс».**~~ **сделано 2026-09-20** (`POST/GET /classes/{id}/assignments`, прогресс в ответе). Оставшееся: срок и статус в интерфейсе. Было: Нет способа назначить тест классу и получить список: нужны `POST /classes/{id}/assignments` (assignment_id, срок, варианты) и `GET /classes/{id}/assignments` со статусом и прогрессом (проверено/всего/на проверке). Без этого вкладка «Тесты» класса и «продолжить проверку» не строятся.
3. **Список заданий учителя.** `GET /constructor/ready-tests` общий на весь сервер и без класса; нужен `GET /assignments` только своих (id, название, класс, дата, статус, число вариантов).
4. **Изоляция данных по учителю.** Сейчас любой `X-Teacher-UUID` самоопределяется, submissions его не проверяют. Нужно: данные привязаны к учителю, чужие класс/сдача → 403/404. Желательно токен (после handshake) вместо голого UUID. → gap 14
5. **Управление классами и учениками.** Есть только неявное создание класса через `bulk-import`. Нужны: создать класс (название, параллель, год), переименовать, архивировать; ученик: изменить, удалить, перевести; стабильный код ученика (`7A-014`) в ответе ростера; дубли имён.
6. **`batch-sync` семантика.** Ответ по каждой сдаче (`results[]`: uuid, inserted/updated/rejected + причина), частичный успех, обязательный `client_submission_uuid`, правило конфликтов (last-write/версия), перепроверка. Проверка, что `student_id`/`class_id`/`assignment_id` принадлежат учителю. → gap 11, 24
7. **Оценка и шкала.** Сервер должен пересчитывать/валидировать `final_grade` по шкале учителя (пример 7/8→4 против 87%→5), отдавать оценку в ответах. Нужны `GET/PUT /teachers/me/preferences` (шкала, `confidence_flag_threshold`). → gap 8, 9

## P1 — нужно для полноценных экранов
8. **Аналитика.**
   - Динамика по времени (по дате/по заданиям) для класса и ученика — сейчас нет, считаем на клиенте из submissions.
   - Единый сводный ответ для Главной: проверено/всего, на проверке, средний результат, средняя оценка.
   - Рекомендация с доказательством (тема, число учеников, «11 из 25 ошибаются в -дан/-дән») одним объектом.
   - `students_performance_table` вынести из основного ответа или пометить опциональным: в продукте запрещены рейтинги.
   - Фильтр аналитики по заданию/периоду.
9. **`GET /submissions`:** пагинация (limit/cursor), фильтры (status, период), сортировка, `GET /submissions/{id}`, статус «на проверке» (`review`), синхронизация «с момента» (`updated_since`) для второго устройства, удаление/отмена сдачи.
10. **Выгрузка:** параметры и `Content-Disposition` с именем файла, `format=csv|xlsx` по контракту, описанные ошибки; выгрузка по классу без выбора задания. (Сейчас работает с `class_id`, но это нигде не описано.)
11. **Печать:** ~~`batch-blanks.pdf`~~ **сделано 2026-09-20**; осталось: свободная зона у маркера 1 и `stu_id` в QR. Было: `batch-blanks.pdf` (бланки на весь класс с `student_id`) — есть в черновике, нет в живом; свободная зона у ArUco-маркера 1 (заголовок наезжает, gap 22); опциональный `stu_id` в QR. → gap 10, 22
12. **Пакет заданий:** версия и `updated_at`/ETag для кэша на телефоне; шаблон листа с координатами (размер маркеров, позиции, строки ответов, поле имени) и версией шаблона; ясная семантика `?variant=` (без параметра — все варианты?). → gap 15, 20
13. **Конструктор:** редактирование и удаление своего теста, `fork` (есть в черновике, нет в живом), удаление своих заданий банка, серверная валидация ответа (только буквы алфавита модели, ≤12 клеток), `is_public_in_bank` с автором.
14. **Пустые клетки и порог:** подтвердить правило пустой клетки и чувствительность (ink < 30) как контракт; подтвердить, что `expected_cells` с `is_empty_allowed` — единственный признак пробелов. → gap 16, 18

## P2 — надёжность и процесс
15. **Контракт OpenAPI:** схема безопасности (`securitySchemes` + `security` на операциях), единый формат ошибок, документированные 4xx/5xx, версия API в `/health`, changelog; заморозка v1.
16. **Стабильность:** сервер периодически отдаёт 502 (наблюдали дважды); нужен постоянный хостинг/SLA на время демо, таймауты, rate limit с понятным 429 + `Retry-After`.
17. **Модель на устройстве:** endpoint или релиз с манифестом модели (версия, SHA-256, порядок классов — `Ә` на индексе 1), возможность обновления; лицензия репозитория `tatar_ocr` и разрешение на использование модели/эталонной предобработки. → gap 17, 18
18. **Приватность:** письменно подтвердить, что сервер не хранит изображения; отключить или пометить `/ocr/*`, `/constructor/scan-task*`, `/api/scan_blank`, `/api/predict_box` как не для приложения; срок хранения; удаление данных учителя/класса.
19. **Стенд для разработки:** отдельный staging, сброс тестовых данных (я создал тестового учителя `…c0de`, задание `TAT-2026-Q1DAB`, класс `KK-PROBE`, сдачу `kk-live-contract-0001`), воспроизводимый демо-сид (7-А, 25 учеников, тест №3, 18 проверено).
20. **Размер отправки:** нужен ли полный список клеток (~7,8 КБ на лист) или достаточно сводки + спорных клеток; гранулярность `teacher_override` (по клетке или по ответу). → gap 23, 24
21. **`GET /teachers/me`:** профиль (имя, школа, шкала, порог) — чтобы восстановить его после переустановки и на втором устройстве. Handshake его только создаёт.
22. **Многостраничные тесты:** в QR есть `page`/`tot`; описать, как страницы одного ученика склеиваются в одну сдачу (ключ, порядок, балл, повторная отправка одной страницы).
23. **Часовой пояс:** `checked_at`/`created_at` сейчас без пояса (`2026-09-19T19:26:56.798000`). Зафиксировать UTC с суффиксом `Z` во всех полях времени.
24. **Варианты:** назначение варианта ученику/классу (`POST /classes/{id}/assignments` + правило раздачи) и отражение в `batch-blanks.pdf`.
25. **Баллы и ответы:** вес задания (`points` вместо жёстких 1) и несколько допустимых ответов на задание (синонимы), иначе учитель правит вручную.
26. **Идемпотентность создания:** `POST /constructor/tests` (и создание заданий/классов) при повторе после таймаута создаёт дубль; нужен `Idempotency-Key` или клиентский uuid.
27. **Предобработка:** `GET /model/manifest` отдаёт `margin_trim_pct 11`, `ink_min_area_pixels 35`, а исходный код 796601e — trim 8%, пустая клетка при ink < 30 px. Что действует на сервере и что должен повторять клиент?
28. **Метрики почерка:** формулы `handwriting_quality_pct`/`status`/`unclear_characters` (порог, окно) — описать.
29. **Версия шаблона листа:** размер клеток ФИО в живом `blank.pdf` изменился (9 → 8 мм) без признака в пакете/манифесте. Нужны `template_version` и геометрия (поле ФИО, строки ответов) в `offline-bundle` или `/model/manifest`.
30. **Изоляция по учителю (уточнение 2026-09-20):** `GET /assignments` и `ready-tests` отдают все тесты любому UUID и даже без заголовка; `GET /classes/{id}/students` и `GET /submissions?class_id=` отдают данные чужого класса. Нужны проверки владельца.
31. **Схема `GET /assignments`:** ответ не описан в OpenAPI (`{}`); добавить `questions_count` и типизировать `assigned_classes`.
